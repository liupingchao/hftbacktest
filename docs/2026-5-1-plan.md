## P2: Working Orders And Order Lifecycle Alignment

Goal: explain and reduce `open_order_mismatch`, especially the latest live test ending with `rest_open_orders=0` and `local_open_orders=1`.

Implementation work:

- Extend live audit with a fuller open-order snapshot: `order_id`, side, price tick, quantity, status, cancellable flag, and whether the order is local-only, REST-visible, or exchange-confirmed.
- Track submit/cancel pending state in audit rows so replay can distinguish resting orders from in-flight orders.
- Model cancel/replace lifecycle windows in backtest replay.
- Add diagnostics that identify the first timestamp where live REST open orders and local working orders diverge.
- Keep startup working-order injection out of scope until the lifecycle diagnostics prove it is needed.

Acceptance:

- Latest OOS run reports a clear cause for each major open-order divergence.
- `open_order_mismatch_pending` rows drop materially, or every remaining row is attributable to an explicit pending lifecycle state.
- Final safety mismatch is no longer an unexplained state.

## P3: API, Throttle, And Latency Guard Refinement

Goal: close the reject-reason gap. Current OOS result shows live API drop rate is much higher than BT: `0.1218` live vs `0.0046` BT.

Implementation work:

- Replay actual live API request/response timing where audit data is available.
- Align live and backtest priority order among `latency_guard`, `quote_throttle`, `api_interval_guard`, and token bucket.
- Model submit/cancel batch behavior more accurately.
- Add per-cycle diagnostics for planned actions, throttled actions, sent actions, and rejected actions.

Acceptance:

- Reject reason match rate improves from about `0.36` to at least `0.55`.
- BT/live API drop rates are within 3-5 percentage points on the OOS sample.
- BT/live latency drop rates remain close.
- Action match rate does not regress below the current OOS baseline.

## P5: Strategy Low-Loss Optimization

Goal: use the aligned replay environment to reduce live test losses before targeting positive PnL.

Implementation work:

- Reduce excessive quote churn and unnecessary cancel/replace activity.
- Control inventory oscillation in the `-0.002 BTC` to `+0.002 BTC` range.
- Tune `base_spread`, `k_inv`, `k_pos`, and quote throttle using archived OOS replay first.
- Keep live position size small during validation.
- Compare live PnL and replay PnL only after open-order and API lifecycle gaps are under control.

Acceptance:

- Safety mismatch does not end normal live tests.
- Trade count and cancel/replace count decrease without materially worsening inventory control.
- Inventory stays closer to zero under the same small-position live profile.
- Short live tests lose less or approach flat PnL before attempting profit-seeking optimization.

## Recommended Next Step

Start with P2. The latest live test ended because of open-order lifecycle divergence, not position divergence. Fixing that is the most direct way to improve live/backtest trust before further strategy optimization.
