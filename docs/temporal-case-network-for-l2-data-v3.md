# 面向 L2 高频时序的时序案例网络：先验驱动的完整方案

## 1. 目标、两条路线与核心原则

### 1.1 要解决的问题

金融市场 L2 高频数据中的分析问题是"结构不良"的：事件边界、有效时间尺度、相似性标准、市场状态划分和任务目标，都不能在系统建设之初被可靠地固定下来。今天认为合理的窗口切分、距离度量和市场分类，随着任务和认识的变化都可能需要修正。

目标是建立一个：

- **可重访**：任何特征、案例和结论都能追溯到原始市场事件；
- **可比较**：同一段时序可以在不同时间尺度、距离度量和市场上下文中比较；
- **可组合**：微观模式可以组成较长事件，多个历史案例可以临时组成当前任务需要的证据结构；
- **可修正**：发现分段、尺度或相似性假设不合适时，可以返回原始证据重新组织；
- **面向任务动态组装**：不预先制造唯一的市场分类体系，而是在预测、解释、异常检测等具体任务中构造局部结构。

### 1.2 两条路线的对比

面对"结构不能预先固定"这个事实，存在两条设计路线。

**路线 A：开放式发现路线。** 既然不知道什么是正确的边界和相似性，就同时维护多种分段提议（固定时钟、市场事件、change-point、motif 发现）、多种特征视图、多种尺度，让无监督算法（Matrix Profile、变长 motif 搜索、discord 检测）在数据中"发现"结构，人再从发现结果中筛选。延迟承诺体现为：第一版什么都算，不排除任何可能性。

这条路线有两个致命问题，且二者是同一个问题的两面：

- **复杂度爆炸**：分段方式 × 特征视图 × 尺度是乘法关系。在约 250 亿行的事件数据上，精确 Matrix Profile 是 O(n²)——50ms 批次级单日 n≈170 万，n²≈3×10¹²，单日单通道就不可行；变长搜索还要再乘一个长度范围因子；由此产生的千万级案例若不加约束地两两建边，图规模到 10¹⁴ 量级。
- **伪结构泛滥**：Matrix Profile 对任何序列——包括纯随机游走——都会返回"最相似的一对"和"最孤立的一段"。它回答"哪里最相似"，不回答"这种相似是否超出随机预期"。在几百亿个候选子序列对中搜索，找到高相似度的巧合是数学必然。搜索空间越大，产出的伪 motif 越多，而校准伪结构所需的统计检验（surrogate 置换）又会进一步放大计算量。开放式搜索在噪声主导的高频序列上，信噪比先天不利。

**路线 B：先验驱动路线（本方案采用）。** 案例总体不由无监督发现生成，而由市场机制和微观结构文献的先验知识定义；挖掘方法降级为"已定型事件族内部的度量工具"和"预算受限的探索通道"。延迟承诺重新定位：

> **延迟承诺的对象是架构，不是第一版的内容。**
> 架构上不承诺"世界只有这些结构"——schema 保留任意分段、任意视图、任意关系的扩展位，一切结论可回溯原始证据、可修正；
> 内容上第一版明确承诺"从哪里开始"——机制事件定义案例总体，文献事实定义特征视图，显式白名单约束组合规模。

这与认知科学中专家处理结构不良领域的方式一致：专家不是无先验地穷举，而是带着强先验进入，在反例出现时修正。系统的开放性由"可修正、可扩展"保证，而不是由"第一版不做选择"保证。

一句话概括本方案：

> **用机制和文献先验组织证据，用挖掘扩展先验的边界，用统计防线保证扩展不引入伪结构。**

## 2. 数据基础（实测核验，2026-07）

数据位置：`/media/liushuai/colorful/binance-futures`，Tardis.dev 标准格式，`.csv.zst` 按 数据流/年/月/日 分区，标的为 Binance Futures BTCUSDT。

### 2.1 实测硬数字

以下数字经过对磁盘数据的直接抽样验证，是后续所有设计决策的边界条件：

| 事实 | 数值 | 设计含义 |
|---|---|---|
| 覆盖范围 | 2025-01-01 至 2026-04-10，共 465 天，八个数据流每天齐全，无缺失日 | 前向验证可用的连续样本 |
| L2 批次间隔 | p10=51ms，p50=52ms，p90=53ms | **交易所侧硬性聚合**：L2 流内不存在亚 50ms 的时序信息，同一批次内的行序不代表真实先后 |
| L2 事件量 | 约 6,000 万行/天，465 天约 250–280 亿行 | 任何全库级 O(n²) 算法不可行 |
| 强平事件 | 约 1,100 个/天（多日抽样均值），全期约 51 万个 | 机制先验锚点；按时间邻近聚簇后约 10⁴–10⁵ 个级联 episode |
| funding 结算 | 每 8 小时一次，全期 1,395 个窗口 | 机制先验锚点 |
| 各流体量 | L2 增量 267G，book_ticker 79G，snapshot_25 28G，trades 12G，snapshot_5 11G，quotes 7.3G，derivative_ticker 855M，liquidations 32M（压缩后） | 处理优先级与存储规划依据 |

### 2.2 数据流分层

一个自然的倾向是把八个数据流并列看待、按体量大小排优先级。本方案按**在先验体系中的角色**分层：

| 层 | 数据流 | 角色 |
|---|---|---|
| 锚点层 | `liquidations`、`derivative_ticker`（funding rate、open interest、mark/index basis） | **定义案例总体的机制事件源**。体量最小（合计不到 1G），信息地位最高 |
| 形态层 | `incremental_book_L2`、`book_snapshot_5`、`book_snapshot_25` | 50ms 以上时间粒度的订单簿形态；快照流用于重建校验 |
| 强度层 | `book_ticker`、`trades` | 亚 50ms 的最优报价与成交强度信息（实测 book_ticker 间隔可达毫秒级） |

`quotes` 与 `book_ticker` 同 schema，前者是后者的抽稀（7.3G vs 79G），信息上是子集：主线只使用 book_ticker，quotes 仅作交叉校验。

### 2.3 时间语义与已知数据质量事实

- `timestamp`：交易所事件时间。L2 流被量化到约 52ms 的批次边界；亚 50ms 的市场微观结构只能从 book_ticker 和 trades 恢复。据此约定：**L2 定义 50ms 以上的形态特征，book_ticker/trades 定义 50ms 以下的强度特征**。
- `local_timestamp`：本地采集时间，用于延迟、乱序和数据质量分析。
- 快照段（`is_snapshot=true`）不只出现在每日文件开头：采集端断线重连会在文件中部插入快照段。重放器必须把**所有**快照段识别为状态重置点。
- `derivative_ticker` 存在字段级空值（如 `open_interest`、`last_price` 在部分行为空），数据质量监控需要覆盖字段级缺失率。
- 数据当前位于 vfat 格式的 USB 外置盘，实测存在瞬时读取失败；该文件系统无权限位、有 4GB 单文件上限。生产计算不能直接在此盘上进行（见阶段 -1）。

## 3. 方法工具箱及其在本方案中的角色

### 3.1 Matrix Profile 与变长搜索

Matrix Profile 对给定长度的每个子序列记录其最近邻的距离和位置，可用于发现 motif（重复模式）、discord（异常模式）和相似片段对应关系。变长扩展（如 VALMOD）同时搜索多个长度，使"事件持续多久"成为待发现变量。

**角色约束**：精确算法 O(n²)，只允许在强下采样序列（1s/10s/1min）上、按日/周分块运行；跨块用 AB-join 增量而非全量 self-join。它不是案例总体的生成引擎，而是（a）已定型事件族内部的相似性度量，（b）探索通道中的候选提名工具（见 §12）。

### 3.2 DTW 与高效 DTW motif 搜索

DTW（动态时间规整）用于比较展开速度不同但阶段结构相似的过程——例如一次在 500ms 内完成的流动性消耗与一次持续 3s 的流动性消耗。SWAMP 一类算法通过下界、剪枝和逐步精化减少昂贵的 DTW 比较，其工程启示是"低成本粗筛，再做弹性时间精排"。

**角色约束**：DTW 精排每对代价 O(L²·w)，只能承受数千对级别的候选集；Sakoe-Chiba 带宽等参数必须显式记录在结果元数据中。

### 3.3 motif 转移图

先发现 motif、再根据 motif 先后关系和预测信息构建有向图的方法（如 MotifDisco），在本方案中对应案例网络的 `conditional_transition` 和 `information_flow` 边。

**措辞纪律**：这类边只能称为条件转移关系、预测信息关系或信息流关系。除非存在额外的识别假设和实验设计，不能解释为结构因果关系。

### 3.4 LangGraph

用状态图组织多步骤任务的编排框架，本方案用其三个机制表达动态检索与反思流程：`Send`（按当前状态动态产生并行任务）、reducer（把并行结果合并进共享状态）、conditional edge（根据证据决定停止/继续/改写策略）。

**角色约束**：LangGraph 不是案例网络本身，只是动态组装流程的可选编排层；案例存储、时序算法和检索系统保持独立。且需注意：`Send` 提供的是编排级并发，对 CPU 密集的 MP/DTW 计算在 Python GIL 下没有真实加速——重计算须由节点内部的 process pool 或外部 worker 承担（见 §14）。

## 4. 先验层级

先验知识有强弱之分，强弱决定其在系统中的角色：

**第 1 档：机制先验（最强，零统计检验代价）。**
由交易所规则直接给定，不是从数据中"发现"的，因此不可能是伪结构，不消耗任何多重比较预算：

- 强平事件与强平级联；
- funding 结算时刻（每 8 小时）及其前后窗口；
- mark price 与 index price 的 basis 及其机制性回归；
- 50ms 聚合边界、tick size、合约规则变更。

→ 用于**定义案例总体**。"这是一次强平级联"是事实，不是假设。

**第 2 档：文献风格化事实（次强，站在已复现研究之上）。**
LOB 微观结构文献中反复复现的规律：Order Flow Imbalance 与队列失衡对短期价格移动的预测力、成交流自相关、波动聚集、大单冲击后的深度回补动力学、spread 扩张-恢复过程。

→ 用于**定义特征视图和次级事件分段**（spread 扩张、OFI 转向等）。用它们切分事件，等于站在几十年文献检验之上，而非从零假设开始。

**第 3 档：挖掘所得（最弱，每条结论欠 surrogate 检验的债）。**
Matrix Profile motif/discord、变长搜索结果、DTW 相似对、learned embedding 的近邻关系。

→ 两种角色：（a）类型内度量工具——在第 1/2 档定义的事件族内部做相似度、检索、聚类；（b）探索通道——提名新的候选事件类型，提名须经机制或文献证据确认才能升级为正式总体（§12）。

对比：开放式发现路线把第 3 档当地基、把强平和衍生品状态仅当作并列数据流之一。本方案倒转这个次序——第 1 档定义总体，第 2 档定义特征，第 3 档作为受约束的工具与扩展通道。

## 5. 任务锁定：用任务选先验

比白名单更强的约束是任务：任务给出标签定义和评估标准，从而决定"哪些视图值得算、哪些相似性值得建边、什么算显著"。第一版锁定一个主任务：

**主任务：强平级联后的流动性演化。**
给定一次强平级联的开局形态与市场上下文，刻画后续深度回补、spread 恢复、价格 excursion 的分布；识别"同样开局、不同结局"的分化条件。

选择理由：

- 事件锚点天然存在（全期约 51 万个强平事件）；
- outcome 定义清晰（恢复时间、多 horizon excursion、深度回补路径）；
- 总体规模（聚簇后 10⁴–10⁵ 个级联）恰好落在 pairwise 相似性方法可行的区间；
- 对执行和做市有直接价值。

备选任务（schema 兼容，暂不实现）：funding 窗口前后的订单流模式；spread 扩张事件的恢复分析；短期价格运动预测。

## 6. 基本知识对象：TemporalCase

系统的基本对象不是"一个 embedding"，而是具有证据、边界、上下文、表示和结果的时序案例：

```text
TemporalCase
├── identity
│   ├── case_id
│   ├── symbol
│   ├── start/end event time
│   ├── population            # 所属总体类型（见 §8）
│   ├── segmentation method + parameters
│   ├── visible_from          # 形态可被检索的时刻 = end event time
│   └── outcome_known_from    # 完整 outcome 可读的时刻 = end + max_horizon
├── evidence
│   ├── raw file/row references
│   ├── reconstructed order-book states
│   └── trades, liquidations, derivative context
├── representations
│   ├── book-state view
│   ├── order-flow view
│   ├── normalized shape（相对形态）
│   ├── absolute intensity（绝对强度）
│   └── optional learned embeddings（带模型版本）
├── context
│   ├── preceding/following cases
│   ├── volatility and liquidity state
│   └── market regime hypotheses
└── outcomes
    ├── future return at multiple horizons
    ├── favorable/adverse excursion
    ├── spread/depth recovery
    └── subsequent event sequence
```

### 6.1 证据与表示必须分离

`evidence` 保存可回访的原始依据，`representations` 保存针对某种比较或任务生成的视图。这一分离允许：

- 更新特征算法而不改变案例身份；
- 使用不同归一化方法比较同一案例；
- 在 embedding 检索后返回原始盘口验证；
- 发现旧表示丢失重要信息时重新计算；
- 保留多个互相竞争的市场解释。

### 6.2 案例允许重叠和多重身份

同一段原始事件可以同时属于一个 1min 固定窗案例、一次 spread 扩张事件、一段强平级联 episode 的组成部分。这些不是重复数据，而是对同一证据的不同组织方式。重叠是设计特性，但它对评估协议有直接后果（见 §13.2）。

### 6.3 可见性双时间线

`visible_from` 与 `outcome_known_from` 区分两件事：案例的**形态**在其结束时刻即可被检索；案例的**完整结果**要等最长 horizon 走完才可读。一个 13:40 结束、最长 horizon 30 分钟的案例，其形态在 13:40 可见，其 outcome 在 14:10 才可知。检索层据此实施 as-of 过滤（§13.3）。

## 7. 第一层：可靠的市场状态重建

在任何相似性、embedding 或图构建之前，先建立确定性的订单簿重放层。

### 7.1 复用优先于自研

工作区内已有的 hftbacktest 项目原生支持 Tardis 格式数据的 L2 订单簿重放。方案的重建层优先评估"在成熟重放器之上加一层薄封装（行号 ↔ 案例 ID 映射、批次 ID 标注）"，仅当可回溯性要求确实无法满足时才自研重放核心。自研理由（任意状态可追溯到原始更新行）大概率可以在成熟重放器之上以映射层实现，而不必重写订单簿维护逻辑。

### 7.2 重建流程

1. 从 `incremental_book_L2` 中识别**所有**快照段（含日初和日中重连），每个快照段作为状态重置点；
2. 按交易所事件时间和文件内顺序应用档位更新；
3. 分别维护 bid 和 ask 的价格到数量映射；
4. 数量归零时删除对应价格档位；
5. 在事件批次后生成需要的订单簿状态，**批次 ID 显式保留**（下游据此区分批内/批间顺序，不把批内行序当真实时序）；
6. 用 book_snapshot_5 和 book_snapshot_25 定期校验重建结果，一致性给出数字化通过率。

### 7.3 必须监控的数据质量

- 时间戳乱序和重复事件；
- 快照或增量缺失；
- 最优买价高于最优卖价（crossed book）；
- 负数量或异常价格；
- 重建状态与独立快照不一致；
- `local_timestamp - timestamp` 的延迟突变；
- 跨日文件边界处的状态连续性；
- 字段级缺失率（含 derivative_ticker 的空值字段）。

### 7.4 存储原则

- 原始 `.csv.zst` 保持只读并有全量 checksum 清单，作为最终证据源（冷备）；
- 工作数据为按日期和数据流分区的 Parquet，位于本地 ext4/xfs 盘；
- 订单簿状态支持检查点恢复；
- 维护原始文件、行区间与案例 ID 之间的映射；
- 数据质量报告和异常区间索引与数据同存。

## 8. 第一版案例总体：显式白名单

开放式路线在此处会并行维护三族分段提议——时钟驱动（各种固定时间/事件数/成交量窗）、市场事件驱动（十余种触发条件）、数据驱动（change-point、motif、discord 边界）——三族分段 × 五类视图 × 多尺度是乘法关系，每加一维都乘一遍存储和计算，且数据驱动分段直接把伪结构引入案例库的地基。

本方案代之以显式白名单。第一版只物化以下六种总体，其余分段方式作为 schema 中预留的扩展位（`segmentation method + parameters` 字段支持任意新方法接入，接入时无需重写既有数据）：

| 总体 | 先验档位 | 边界定义 | 预估规模（465 天） |
|---|---|---|---|
| 强平级联 | 机制 | 强平事件按时间邻近聚簇，前后各取缓冲窗 | 10⁴–10⁵ |
| funding 窗口 | 机制 | 结算时刻 ± 固定窗 | 1,395 |
| spread 扩张 | 文献 | spread 超过滚动分位阈值 → 回落 | 10⁴–10⁵ |
| OFI 转向 | 文献 | OFI 滚动符号显著翻转 | 10⁵ 级 |
| 1min 固定窗 | 基线 | 固定时钟 | 约 6.7×10⁵ |
| 1s 固定窗 | 基线 | 固定时钟 | 仅在事件总体邻域内按需物化 |

说明：

- 固定窗总体仅作统计基线和对照组。1s 窗不全量物化（465 天 × 86,400 ≈ 4×10⁷ 个，全量既无必要也不经济）；
- 各总体的边界参数（聚簇时间窗、分位阈值、翻转显著性标准）在阶段 2 用一个月数据标定后冻结并记录版本；
- 案例间的 `overlaps` / `contains` / `component_of` 关系显式保存，多尺度结构（微观盘口变化 → 中观事件 → 较长市场状态）由这些关系承载，而不是由预先枚举的尺度族承载。

## 9. 特征视图：每案例两个序列视图加轻量上下文

开放式路线会为每个案例维护五类视图（原始事件、订单簿状态、订单流、相对/绝对、上下文）的全组合。第一版收敛为两个序列视图 + 一个非序列上下文，其余视图作为表示层的扩展位。

### 9.1 订单簿状态视图（源自 L2 + snapshot 校验，时间粒度 ≥50ms）

- spread；
- mid-price 与 microprice；
- 各相对档位深度（价格表示为 `(price - mid_price) / tick_size`）；
- depth imbalance、depth slope；
- queue depletion、book pressure。

### 9.2 订单流视图（亚 50ms 部分源自 book_ticker/trades）

- OFI（Order Flow Imbalance）；
- signed trade volume、主动买卖比例；
- add/cancel/trade 强度（L2 部分按批次计算）；
- 成交冲击与价格响应；
- 事件到达间隔及其突变（仅对 book_ticker/trades 有亚 50ms 意义）。

### 9.3 相对形态与绝对强度分开保存

z-normalize 后的形态只是视图之一。必须同时保存实际成交额、挂单量、波动率、市场深度、事件强度、流动性恢复时间等绝对量。否则两个归一化形态相同、但市场冲击规模相差百倍的案例会被错误地视为等价。

### 9.4 上下文（轻量、非序列）

- 近期波动与趋势；
- spread 与深度分位数；
- 成交和撤单活跃度；
- open interest、funding rate、mark-index basis；
- 是否邻近强平事件；
- 时间段与数据质量状态。

### 9.5 尺度约定

第一版只做两层：事件自身尺度 + 1min 上下文尺度。不维护开放的多尺度族；更长尺度的结构由案例间的 `component_of` 关系组合表达。

## 10. 类型内相似性与案例网络

### 10.1 作用域约束

所有相似性计算与相似类建边**限定在同一总体内部**。跨总体只保留时序关系（`precedes`/`follows`）和结构关系（`overlaps`/`contains`/`component_of`）。

理由：在 10⁴–10⁵ 规模的类型化总体内，"粗筛（下采样投影 + MP AB-join / 欧氏 kNN）→ 精排（受约束 DTW，候选 ≤ 数千对/查询）→ 聚类/原型"是单机可行的计算；且总体成员资格由机制事件保证，挖掘只回答"这类真实事件内部有哪几种展开方式"这种**条件在真实事件上**的问题——相比在全库任意两段之间搜索相似，多重比较的搜索空间缩小五到六个数量级，伪结构问题从源头缓解。

### 10.2 节点层次

```text
Raw Case → Prototype → Episode → Regime
```

- `Raw Case`：直接对应一段可回访的市场证据；
- `Prototype`：一组相似案例的代表，不删除成员间差异；
- `Episode`：由多个微观案例组成的较长过程；
- `Regime`：对一段时期流动性、波动和交易行为的**暂时性**描述——可修正的上下文假设，不是永久市场类别。

### 10.3 关系类型

| 关系 | 含义 |
|---|---|
| `shape_similar` | 在某个形态视图和距离度量下相似 |
| `elastic_similar` | 经 DTW 时间规整后相似 |
| `context_similar` | 市场上下文相似 |
| `precedes` / `follows` | 真实时间上的先后关系 |
| `overlaps` / `contains` | 案例边界之间的关系 |
| `component_of` | 微观模式组成较长 episode |
| `same_pattern_different_outcome` | 形态相近但后续结果不同 |
| `different_pattern_same_outcome` | 形态不同但后续结果相近 |
| `counterexample_of` | 对某条规则或原型解释构成反例 |
| `conditional_transition` | 给定上下文时的模式转移 |
| `information_flow` | 一个模式对后续模式具有预测信息 |

其中 `same_pattern_different_outcome` 与 `counterexample_of` 是主任务（"同样开局、不同结局"）的核心承载——这类关系只有在类型化总体上才真正有意义："同样的级联开局，为什么这次深度恢复了、那次没有"是可回答的问题，"全库范围内任意两段相似"不是。

### 10.4 图稀疏化预算（硬约束）

- 相似类边（`shape_similar`/`elastic_similar`/`context_similar`）：每节点每关系类型 top-k（k≤10），且必须通过显著性阈值（§13.1）；
- 时序类边：只连同总体内时间邻域的前后 N 个案例；
- 结构类边：按定义生成，天然有界；
- 对照类边：由相似类边派生，随 top-k 自然有界。

不设预算的后果是明确的：千万级案例的稠密相似图在 10¹⁴ 边量级，既不可存储也不可检索。

### 10.5 边的元数据

每条相似关系必须记录：使用的表示、距离度量及参数、比较尺度、是否归一化、关系建立时间、算法版本、支持该关系的原始案例、**显著性字段（经验 p 值 + surrogate 方法，见 §13.1）**、**图构建时间（服务于 as-of 版本截断，见 §13.3）**。

"相似"不是事实常量，而是带有方法、上下文和显著性的判断。

## 11. 发现与检索

### 11.1 分层发现策略

1. 用低成本投影视图（下采样序列）和 Matrix Profile 在总体内发现候选相似对与异常；
2. 用变长方法搜索持续时间不固定的过程（仍限总体内部、下采样序列）；
3. 用受约束 DTW 对候选做弹性时间精排；
4. 用上下文条件过滤不具可比性的市场状态；
5. 数据规模扩大后训练 embedding 提高候选召回效率；
6. 回到原始事件或重建状态做最终验证。

```text
低成本粗检索
    ↓
多路候选集合
    ↓
DTW、精确特征或原始状态精排
    ↓
上下文与结果对照
    ↓
构造当前任务的案例子图
```

### 11.2 embedding 的正确位置

embedding 适合：大规模近似搜索；学习手工距离难以表达的局部模式；对多通道序列生成任务相关表示。

embedding 不应：成为案例的唯一存储形式；混合所有尺度和上下文后只输出一个向量；取代精确距离、时间关系和原始证据；被直接解释为市场机制或因果结构。

同一案例可以分别保存订单簿形态、订单流、上下文等多个 embedding，记录模型版本；索引按月 walk-forward 版本化（§13.3）。

### 11.3 检索不能只返回最近邻

一次查询应并行获取：形态最近邻；DTW 弹性相似案例；相同上下文案例；不同市场状态下的相似形态；当前模式的典型前驱和后继；**相同形态但结果相反的案例**；异常或低相似度案例；支持和反驳当前解释的案例。

随后用 late fusion 或 MMR（最大边际相关性）平衡相关性与多样性，避免结果被单一模式占满。

### 11.4 as-of 是检索 API 的强制参数

每次查询必须携带 `as_of_time`，检索层据此过滤（详见 §13.3）。这不是评估阶段的纪律，而是接口签名的一部分。

## 12. 挖掘作为探索通道

先验驱动不等于封闭。开放式发现保留为一条独立的旁路通道，用于扩展先验的边界，规则如下：

1. 只在强下采样序列（1s/10s/1min）上运行，按日/周分块，禁止全库级 O(n²)；
2. 每一批发现必须通过 surrogate 校准（§13.1）才能进入候选池；
3. 候选池中的模式只能**提名**新事件类型；提名升级为正式总体，需要机制解释（能对应到交易所规则或参与者行为机制）或文献对应（已有研究复现过同类现象）；
4. 通道有显式计算预算（如每月不超过既定 GPU/CPU 小时数）；预算内做不完就缩小搜索范围，**不允许降低检验标准来换速度**。

这条通道的产出物是"候选事件类型提名报告"，而不是直接写入案例网络的边。

## 13. 三道统计防线

这套系统的每一层都在主动搜索历史数据中"好看"的结构，而搜索本身会制造好看：模式发现搜索相似性，模型评估搜索预测力，案例检索搜索证据。三道防线分别封住三个口子，且全部做成结构（schema 字段、评估协议、API 参数），不依赖研究时的自觉。

### 13.1 surrogate 显著性校准 → 边 schema 的必填字段

**封住的口子**：模式发现的多重比较。在 465 天 × 多通道上搜索，找到高相似度巧合是数学必然；伪 motif 一旦入库就会固化为带元数据的"知识"，污染下游一切推理。

**做法**：对每类挖掘所得关系，用 block-shuffle（按小时/日为块，保留块内自相关与波动聚集）或相位随机化（保留功率谱、破坏非线性结构）生成 ≥100 组 surrogate 序列，在其上跑完全相同的发现流程得到零分布；真实模式的距离/统计量须优于零分布的 1% 分位才允许入库，经验 p 值与 surrogate 方法写入边元数据。

机制先验定义的总体成员资格不需要此检验——这正是把机制事件放在第 1 档的原因：它们的边界由交易所规则定义，不由搜索产生。

### 13.2 purged walk-forward → 评估协议

**封住的口子**：案例重叠 + 多 horizon 标签造成的训练/验证泄漏。案例允许重叠是设计特性（§6.2），但它使"按案例随机采样切分"必然让同一段盘口同时出现在训练与验证中；outcome 标签向前延伸最长 horizon，使名义上在切分边界之前的训练案例实际用到了边界之后的数据。

**做法**：

- 只按时间段切分，训练期 → 验证期 → 测试期严格前向推进，禁止按案例采样切分；
- Purge：剔除"证据区间 ∪ 标签区间"与验证期相交的所有训练案例（区间并集的判断利用已保存的 `overlaps`/`contains` 关系）；
- Embargo：验证期结束后留出缓冲（不短于波动聚集的时间尺度，小时级起步）再开始下一轮训练期；
- 置信区间用块自助法（按日/小时为块重采样）：相邻案例的标签强自相关，有效样本量远小于案例数，逐案例独立假设会把真实不确定性低估一个数量级；
- 单独评估 regime 变化时期，不让平稳期的表现掩盖转换期的失效。

### 13.3 as-of 检索约束 → 检索 API 与索引版本化

**封住的口子**：案例检索的前视泄漏。这是案例库架构自身引入的新泄漏通道，且最隐蔽——系统演示时无懈可击（检索出的历史案例确实相似、outcome 分布确实指向正确方向、解释链条完整），因为它确实在不被察觉地读未来。具体两个口子：

- **未走完的 outcome**：模拟历史时刻 t 的查询若检索到一个刚结束不久的案例并读其 outcome，就等于偷看 t 之后的行情。规则：查询时刻 t 只能读取 `outcome_known_from ≤ t` 的案例 outcome（形态可见性与 outcome 可知性是两条时间线，§6.3）；
- **用全期数据构建的索引和图**：embedding 模型、原型、regime 划分、边的 top-k 排名若在全部 465 天上一次性算出，则历史时点的查询会用到未来数据对结构的贡献。规则：边带构建时间，索引按月 walk-forward 重建，回测只允许使用 `build_time ≤ as_of_time` 的版本；正式评估前须做一次"全量图 vs 截断图"的检索差异对照实验，量化该泄漏在本场景中的实际大小。

**生效时点**：从案例浏览器（阶段 3）起强制。浏览器一旦允许"看着完整 outcome 挑相似案例"，研究者的直觉就会被污染，之后所有结论都沾上这个偏差。

## 14. 动态组装与结构化反思

动态组装的输入可以是一个尚未完成的当前 episode，也可以是异常检测、历史解释或策略研究问题。

### 14.1 并行多路检索

通过 LangGraph 的 `Send`（或任何等价并行机制）同时执行：

```text
当前案例或部分 episode（带 as_of_time）
├── 形态最近邻检索
├── DTW 弹性相似检索
├── embedding 候选召回
├── 相同上下文 / 相同 regime 检索
├── 前驱/后继图检索
├── 异常与低相似度检索
└── 反例与相反结果检索
```

工程分工：`Send` 只做任务分发与结果收集（编排级并发）；MP/DTW 等 CPU 密集计算由检索节点内部的 process pool 或外部 worker 承担（Python GIL 下编排级并发无真实加速）；长流程启用 checkpointer 持久化，支持中断恢复。

### 14.2 保留差异的结果合并

reducer 不合并自然语言摘要，而合并结构化证据：

```text
RetrievedEvidence
├── case_id
├── source retrieval channel
├── segmentation and scale
├── representation and distance（含显著性）
├── raw evidence references
├── context
├── outcomes（经 as-of 过滤）
├── graph relations
└── supports / contradicts which hypothesis
```

合并的目的不是强制形成共识，而是保存多个视角及其冲突。

### 14.3 结构化反思

反思步骤检查：

- 当前 episode 的起点是否选错；
- 应观察 500ms、5s 还是 1min；
- 当前市场状态假设是否合理；
- 形态相似是否只是归一化造成（对照绝对强度视图）；
- 是否存在相同形态但结果相反的案例；
- 是否遗漏成交簇、强平或持仓量变化；
- 当前距离度量是否适合该任务；
- 新一轮检索是否仍在产生实质性新证据。

反思输出是结构化决策：

```text
ReflectionDecision
├── sufficient_evidence: bool
├── missing_evidence_types: [...]
├── segmentation_revisions: [...]
├── scale_revisions: [...]
├── context_revisions: [...]
├── counterexample_queries: [...]
├── next_retrieval_actions: [...]
└── stop_reason
```

### 14.4 分层终止

终止判据分两层，次序固定：

1. **确定性判据先行**（在 conditional edge 中以代码执行，不问模型）：as-of 合法性检查；计算/延迟预算；证据类型覆盖度（关键类型是否已检索）；信息增益阈值（连续 N 轮无实质新证据）；总查询数上限；
2. **语义判断殿后**（交给 LLM 反思节点）：当前证据是否支持假设、缺少哪类证据、反例是否已被认真对待。

终止不依赖"所有结果达成一致"，而依据：关键证据类型已覆盖；支持案例和反例均已检查；多轮结论趋于稳定；新增信息增益低于阈值；达到预算；当前不确定性已被明确记录。

## 15. 面向具体任务的临时结构

案例网络本身不直接等于预测模型。每个任务从网络中动态提取不同的局部子图。

### 15.1 强平级联后的流动性演化（主任务）

重点组装：级联开局的订单簿/订单流形态；相似上下文（波动、OI、funding 状态）下的历史级联；后续深度回补与 spread 恢复路径的分布；同开局不同结局的案例对及其分化条件；多 horizon 的 excursion 分布。

### 15.2 流动性恢复分析（备选）

重点组装：深度骤降和 spread 扩张案例；恢复过程的变长模式；撤单、成交和重新挂单的相对次序；不同 regime 下的恢复时间分布。

### 15.3 异常与新型市场行为检测（备选）

重点组装：类型内低相似度案例与 discord；与已知模式的局部相似部分；数据质量证据（排除采集异常伪装的市场异常）；后续是否演化为已知 episode。

### 15.4 历史事件解释（备选）

重点组装：事件前、中、后的多尺度案例；前驱和后继关系；最相似历史过程；关键差异与反例；支持每个解释的原始盘口证据。

## 16. 分阶段实施路线

### 阶段 -1：存储与环境

范围：

- 生成全量 checksum 清单；工作副本迁出 vfat USB 盘至本地 ext4/xfs（实测该盘有瞬时读取失败；剩余空间 193G 不足以再容纳 Parquet 副本，存储去向需先规划）；原始盘转为冷备证据源；
- 新建 conda 环境（python ≥ 3.11）：polars/duckdb（该数据量禁用 pandas 逐文件读）、zstandard、stumpy、受约束 DTW 实现；确认 GPU 可用性（决定 Matrix Profile 可行规模上限）；
- 评估复用 hftbacktest 的 Tardis 格式 L2 重放能力（§7.1）。

验收：数据迁移完成且 checksum 全过；新环境跑通单文件解压-解析-统计；重放器"复用/自研"结论明确并记录理由。

### 阶段 0：单小时数据重放

范围：选择一天中的一个代表性小时；重建 L2 订单簿；对齐 trades、book_ticker 和 snapshot；输出数据质量报告和可视化回放。

验收：

- 可稳定重放，任意状态可追溯到原始更新行；
- 快照重置语义正确：识别所有快照段（含日中重连）并作状态重置点；
- 与 book_snapshot_25 的逐档一致性给出数字阈值（如对齐时刻前 25 档完全一致率 ≥99.9%），不接受"基本一致"；
- 52ms 批次边界以批次 ID 形式在重放输出中显式保留；
- 延迟、乱序和异常区间可定位。

### 阶段 1：一个月的状态与特征层

范围：优先处理 L2、trades、book_ticker、top-5 snapshot 和 derivative_ticker；只生成 §9 白名单的两个特征视图 + 上下文；建立 Parquet 分区和检查点。

验收：

- 跨日连续性明确；
- 特征计算可重复；
- 每个特征都能回到原始证据；
- 不依赖一次性加载全部数据；
- 数据质量报告含字段级缺失率。

### 阶段 2：机制事件案例库

范围：

- 实现 §8 的六种总体；边界参数用一个月数据标定后冻结并记录版本；
- 案例带 `population` 标签、双时间线字段、`overlaps`/`contains`/`component_of` 关系；
- 先在一个月数据上出总体规模、事件分布、边界稳定性报告，再扩全期。

验收：

- 同一原始区间可被多种总体引用；
- 修改边界参数不需要重写原始数据；
- 能从案例定位到原始事件和上下文；
- 六总体的全期规模与 §8 预估同数量级（数量级偏离即触发边界定义复查）。

### 阶段 3：类型内相似性与案例浏览器

范围：

- 在强平级联总体上先跑通"粗筛 → DTW 精排"管线，再推广到其他总体；
- 支持订单簿状态视图与订单流视图两种比较基准；
- 建立案例对比界面，展示原始状态、归一化形态、绝对强度、上下文和结果；
- **浏览器强制 as-of 模式**：不带 as_of_time 无法浏览 outcome。

验收：

- 可以解释两个案例为何相似（度量、参数、显著性可展示）；
- 可以查看它们在哪些方面不同；
- 能主动找到同形异果案例；
- 搜索结果不是单一距离排序（多通道 + MMR）。

### 阶段 4：类型内案例网络

范围：

- 按 §10 的作用域和稀疏化预算建立时序、相似性、包含、反例和条件转移关系；
- 形成 Raw Case、Prototype、Episode、Regime 多层节点；
- 记录所有边的方法来源、版本、显著性和构建时间。

验收：

- 可以从一个案例遍历前驱、后继和组成关系；
- 可以比较不同上下文下同类事件的后继分布；
- 图中结论可回到支持案例；
- 图规模在预算内（每节点边数有上界），全部边带构建时间与显著性字段。

### 阶段 5：多视图向量索引

范围：

- 分别为订单簿形态、订单流和上下文训练或选择表示模型；
- embedding 只用于候选召回，DTW、上下文和原始状态负责精排；
- 索引按月 walk-forward 版本化。

验收：

- 向量索引失效或重建时不影响案例证据；
- 不同 embedding 可以并存和比较，均带模型版本；
- 新方法可以基于同一案例库重新生成索引；
- 回测查询可按 as_of_time 选择索引版本。

### 阶段 6：动态查询与结构化反思

范围：

- 实现 §14 的并行多路检索（编排层 + process pool 分工）与结构化证据合并；
- 实现分层终止（确定性判据 + LLM 语义判断）；
- 长流程 checkpointer 持久化。

验收：

- 系统能说明选择了哪些案例和关系；
- 能说明哪些案例构成反例；
- 能记录为什么继续或停止检索，且确定性判据与 LLM 判断在日志中可区分；
- 输出是带来源的案例子图，而不仅是文本答案；
- 任一次查询可复现：as_of_time + 索引版本 + 边版本唯一确定检索结果。

### 阶段 7：探索通道

范围：按 §12 规则运行开放式 motif/discord 发现，产出候选事件类型提名报告。

验收：每份提名附 surrogate 显著性证据与机制/文献对应初步分析；无一条未校准的挖掘结果直接进入案例网络。

## 17. 评估方法

### 17.1 数据与系统正确性

- 订单簿重建准确率（与 snapshot_5/25 及 book_ticker 的一致性通过率）；
- 原始事件追溯成功率；
- 跨日和异常恢复能力；
- 查询延迟、存储成本和增量更新成本。

### 17.2 检索质量

- 同总体内相似案例的形态和上下文一致性；
- 同形异果和反例召回率；
- 结果多样性（多通道贡献分布）；
- 不同距离度量下结论的稳定性；
- 挖掘所得关系的 surrogate 显著性分布；
- 专家对案例可比性的判断。

### 17.3 面向任务的有效性

- 全部采用 purged walk-forward（含 embargo），置信区间用块自助法；
- 单独评估 regime 变化时期；
- 主任务（强平级联流动性演化）设三条基线：无条件恢复时间分布、仅上下文特征的回归、固定窗 + 单一 embedding 检索——案例网络须显著优于三者才算有效；
- 不只评估方向准确率，还评估概率校准、路径风险和稳定性；
- 检查使用反例和上下文后是否减少过度确信；
- 正式评估前完成"全量图 vs 截断图"检索差异对照实验（§13.3）。

未来结果不定义为单一"上涨/下跌"标签：至少保留多个预测周期、路径形态、最大有利/不利变化、流动性恢复和后续事件序列。

## 18. 需要避免的做法

- 一开始处理全部 403 GB；
- 在 vfat 外置盘上直接做生产计算；
- 把 top-25 档位直接展平成一个向量后只使用余弦距离；
- 只保留 z-normalized 形态，丢失市场规模和事件强度；
- 将固定时间窗口当作唯一案例边界；
- 忽略 52ms 聚合边界，把 L2 批内行序当真实时序；
- 把无监督挖掘所得直接写入案例网络而不过 surrogate 校准；
- 在全库（而非类型内）范围做 pairwise 相似性；
- 只返回最近邻，不检索反例和相反结果；
- 将信息流或预测转移直接称为因果关系；
- 按案例采样切分训练/验证（必须按时间段 + purge/embargo）；
- 检索接口不带 as_of_time，或案例浏览器允许无 as-of 浏览 outcome；
- 用全期数据构建的索引/图评估历史时点的查询而不做版本截断；
- 让自然语言摘要取代结构化证据；
- 让聚类标签成为不可修正的市场本体；
- 为了当前预测任务删除未来可能有用的原始上下文。

## 19. 最终系统形态

```text
只读原始事件仓库（checksum 冷备）
        ↓
可验证的市场状态重建层（复用成熟重放器 + 案例映射薄层）
        ↓
机制事件驱动的类型化案例库（白名单总体 + schema 扩展位）
        ↓
类型内多视图算法与版本化索引（surrogate 校准 + 稀疏化预算）
        ↓
带来源、显著性与反例的时序案例网络（as-of 可见性）
        ↓
面向任务的动态组装与分层终止反思引擎
        ↓
（旁路）预算化探索通道：提名新事件类型 → 先验确认 → 升级为总体
```

最终产物不是一个"L2 向量数据库"，也不是一个预先固定的市场分类体系，而是：

> **原始事件仓库 + 可重建状态层 + 机制事件案例库 + 多视图版本化索引 + 带显著性的时序案例图 + 分层终止的动态组装引擎。**

系统不声称"从数据中发现结构"，而是：**用机制和文献先验组织证据，用挖掘扩展先验的边界，用统计防线保证扩展不引入伪结构。** Matrix Profile、DTW、embedding、图算法和预测模型各自承担与其证据强度相称的职责；开放性由架构的可扩展与结论的可修正保证，而不是由第一版不做选择保证。
