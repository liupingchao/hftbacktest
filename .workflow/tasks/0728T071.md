action：
- 由一次性 x86_64 构建节点构建 release binary，记录源码、lockfile 和
  binary SHA-256；构建节点不进入候选排名并在产物回收后立即终止。
- 先启动 2 台 canary，执行短时双交易所 smoke 和 recorder benchmark；
  canary 失败时不扩容。
- canary 通过后扩展到总计 10 台 x86_64 `xlarge` 候选实例。
- 根据 AWS `trading-latency-benchmark` commit `8dad243` 的 hunting
  设计，每个候选实例使用独立 cluster placement group，以增加底层网络
  placement 覆盖；同一 AZ、AMI、子网、安全组、instance profile、
  binary 和 exact command 保持不变。
- 候选矩阵固定为 10 个 x86_64 `xlarge`：`c7i.xlarge`、
  `c7a.xlarge`、`c6in.xlarge`、`c5n.xlarge`、`m7i.xlarge`、
  `m7a.xlarge`、`r7i.xlarge`、`r7a.xlarge`、`m5zn.xlarge` 和
  `c6i.xlarge`；容量失败使用预先记录的 x86_64 `xlarge` 备选补足，
  不静默缩小样本。
- 每次正式采集先丢弃 100 条 warmup BBO，warmup 完成后才开始完整
  900 秒 measurement window。
- 每台在采集前配置 Amazon Time Sync Service 的 Chrony，要求 Leap
  status Normal 且绝对 system offset 不高于 `100us`。保存 root delay、
  root dispersion、PHC/ENA timestamp capability 和可计算 clock error
  bound；未通过时钟门禁的 feed-network 结果不得进入推荐排名。
- 每台同时运行 Binance Futures `BTCUSDT` 与 Hyperliquid `BTC` 公共
  probe 900 秒；不访问 credential/private/account/order/cancel 接口。
- 保存 instance/CPU/kernel/NTP/DNS/route metadata、benchmark JSON、双
  venue raw NDJSON、summary、日志、offload/IRQ/clocksource 状态和
  SHA-256 manifest。
- 回收压缩 raw evidence；Git 只跟踪汇总、排名、manifest 和原始压缩包
  哈希，避免把大体积 raw trace 加入版本库。
- 无论成功、失败或本地中断，都提供基于 task/run tags 和 state file 的
  独立 cleanup；结束时验证不存在 T071 pending/running/stopping 实例。

blockers：
- 本任务测量公共行情和本地 probe 链路，不证明真实订单 ACK/fill/PnL。
- `feed_network` 依赖交易所时间戳与实例墙钟；NTP 未同步或负样本必须
  显式降级，不能用于推荐结论。
- 本轮不直接套用参考项目的全量 OS tuning。该 playbook 会重启、改变
  CPU/IRQ/ENA/内存变量并禁用 SSM；本任务先做统一未调优基线，胜出实例
  的 tuning A/B 另立任务。
