需求目标：
- 在 `0514T003` mid-markout pricing signal 研究之后，定义后续 maker execution outcome 研究必须回答的问题。
- 目标不是重复 T003 的 raw future-mid Spearman，而是补齐 maker 策略从“预测价格”到“可执行挂单收益”的关键证据。

- 后续研究不能假设单一相关性算法适合所有 outcome；必须按 label 类型选择统计方法，并明确哪些指标只是描述性相关，哪些可以作为后续建模候选。

必须覆盖的问题：
- fill probability：
  - 挂单后是否成交。
  - 挂单后多久成交。
  - 不同信号 bucket 下的 fill rate / time-to-fill 是否不同。
- adverse selection after fill：
  - 成交后价格是否继续朝不利方向走。
  - fill 后 `100ms / 500ms / 1s / 5s` side-adjusted markout。
  - bad-fill bucket 是否集中在某些 signal / latency / top5 state。
- spread capture：
  - 成交价相对 future mid 是否真的赚到 spread。
  - spread capture 是否被 adverse selection 或 latency 侵蚀。
- queue / priority proxy：
  - 挂单时相对盘口位置、top1/top5 size、book age、join age、latency 是否影响 fill。
  - 只能定义为 proxy，不得声明 exact queue position。
- cancel-to-fill race：
  - cancel_requested 后是否仍然成交。
  - cancel request 到 fill 的延迟和不利 markout。
  - 该风险是否集中在特定 signal bucket 或 inventory state。
- post-only / reject / throttle：
  - 信号状态是否对应更高 post-only reject、API reject、throttle、drop 或 churn。
  - quote update / cancel-readd 行为是否因信号导致更高操作成本。
- inventory impact：
  - 信号是否只在某些 position / inventory_score 状态有效。
  - 信号是否导致库存向坏方向累积，或使 inventory reduction 更困难。
- quote placement / distance：
  - quote 是挂在 touch、inside、step-back，还是距离 BBO 多个 tick。
  - quote distance、tick rounding、crossed/post-only risk 是否影响 fill、reject 和 markout。
- missed-fill / opportunity cost：
  - 未成交后 mid 是否朝有利方向移动。
  - 保守挂单是否减少 adverse selection 的同时错过可赚钱 fill。
  - 不同 signal bucket 下的 missed opportunity 是否集中。
- realized PnL decomposition：
  - 将 execution outcome 拆为 realized/effective spread、fee-adjusted spread capture、inventory mark-to-market PnL 和 per-fill expected value。
  - 区分 gross spread capture 与扣费、markout、库存后是否仍为正。
- tail risk：
  - 不只看平均 markout，还要看 p1/p5/worst adverse markout、极端 cancel-fill markout 和库存尾部暴露。
  - 识别少数高损 fill 是否集中在特定 signal / latency / inventory bucket。
- partial-fill / order lifecycle：
  - 区分 full fill、partial fill、remaining qty、multiple fills、cancel ack 前后状态和最终 order state。
  - 订单生命周期 label 必须能解释 fill ratio，而不是只用是否成交。
- inventory cycle：
  - 除 position before/after，还要看 time-to-flat、max inventory excursion、inventory holding time 和 crossing-zero cycle reset。
  - 判断 signal 是否提高库存回归效率，或延长坏库存持有。
- sample validity / censoring：
  - 对每个 horizon 标记订单是否有足够观测窗口。
  - 对未成交订单区分 true non-fill、right-censored、tail-truncated 和 missing lifecycle。
  - fill probability / time-to-fill 结论必须报告 censoring 口径。

建议的 label 大类：
- submit 后 `100ms / 500ms / 1s / 5s` 是否 fill。
- submit 后 time-to-fill。
- fill 后 `100ms / 500ms / 1s / 5s` side-adjusted markout。
- spread capture：fill price vs future mid / side-adjusted captured ticks。
- fill-after-cancel-request。
- reject / throttle / drop / churn bucket。
- inventory transition：position before/after、inventory_score bucket、inventory-reducing vs inventory-increasing fill。
- quote placement / distance：touch/inside/step-back、distance-to-BBO ticks、crossed/post-only-risk、rounding bucket。
- missed-fill / opportunity cost：unfilled-then-favorable-mid-move、missed spread capture、conservative-quote bucket。
- realized PnL decomposition：realized spread、effective spread、fee-adjusted captured ticks、inventory mark-to-market component、per-fill net EV proxy。
- tail risk：p1/p5/worst side-adjusted markout、tail adverse bucket、tail cancel-fill bucket、tail inventory exposure。
- partial-fill / lifecycle：full/partial/no fill、fill ratio、remaining qty、multi-fill count、final order state、cancel ack before/after fill。
- inventory cycle：time-to-flat、max inventory excursion、inventory holding time、cycle reset after crossing zero。
- sample validity / censoring：horizon-observable flag、right-censored flag、tail-truncated flag、missing lifecycle flag。

统计方法要求：
- 连续 label：
  - 适用对象：fill 后 side-adjusted markout、spread capture、fee-adjusted captured ticks、inventory mark-to-market、time-to-flat、inventory holding time。
  - 方法：Spearman rank correlation 作为主相关性指标，Pearson 只作为线性辅助；必须同时报告 quantile bucket mean/median、top-bottom spread、bucket monotonicity 和前后时间段稳定性。
- 二元 label：
  - 适用对象：horizon 内是否 fill、fill-after-cancel-request、是否 reject/throttle/drop、是否 missed opportunity、是否 tail adverse。
  - 方法：按 signal quantile bucket 报告 event rate、lift vs baseline、odds ratio；如进入建模阶段，logistic regression / AUC 只能作为辅助排序，不得替代 bucket 解释。
- time-to-event / censored label：
  - 适用对象：time-to-fill、time-to-cancel-ack、time-to-flat、horizon 内未观察到 fill 的订单。
  - 方法：必须显式处理 right censoring；优先使用 Kaplan-Meier / discrete hazard bucket 或 Cox-style hazard 作为后续模型候选；不得把 censored non-fill 简单当作普通连续值做 Spearman。
- count / rate label：
  - 适用对象：churn 次数、cancel/readd 次数、reject count、partial fill count、multi-fill count、API budget per fill。
  - 方法：按 bucket 报告 count rate / exposure-normalized rate / rate ratio；如进入建模阶段，可用 Poisson 或 negative-binomial 作为辅助，不得只看原始 count。
- 多分类 / lifecycle label：
  - 适用对象：full/partial/no fill、final order state、cancel ack before/after fill、inventory cycle state。
  - 方法：contingency table、conditional probability、mutual information 或 one-vs-rest event-rate lift；必须保留样本数，避免稀疏 bucket 过度解释。
- tail label：
  - 适用对象：p1/p5/worst adverse markout、极端 cancel-fill、极端库存暴露。
  - 方法：tail quantile、CVaR-like tail mean、worst bucket concentration 和 exceedance rate；不得只用均值或 Spearman 判断风险。
- placement / opportunity-cost label：
  - 适用对象：distance-to-BBO、touch/inside/step-back、unfilled-then-favorable-move、missed spread capture。
  - 方法：按 placement bucket 和 signal bucket 做二维 bucket table，报告 fill-rate / missed-opportunity-rate / adverse-markout / net-EV proxy 的 tradeoff；必要时用 logistic / hazard 模型辅助，但主结论必须保留分桶 tradeoff。
- 所有 label：
  - 必须报告 rows、valid rows、missing rows、censored rows、bucket sample count 和时间 split 稳定性。
  - 必须区分 observed-only 相关性与 counterfactual 结论；不得把相关性分析解释为“换价/不撤/改信号就一定成交或盈利”。

边界：

- 后续实现任务必须明确 observed-only 边界：只分析实际发生的 live audit outcomes，不声称“如果换价/不撤/改信号就一定成交”的 counterfactual 结论。
- 后续实现任务不能代替 queue/fill model calibration；exact queue proof 仍需单独任务。
- 后续结论只能作为 fair/reservation adjustment 或 quote-control design 的输入，不直接授权策略实现、默认开启、live 或 production promotion。
