# QA 验收模板

这份模板给 QA 验收线程使用。

QA 应始终把**最新有效结果**写进项目固定的 QA 文档。

整段文本必须用**可直接复制的 Markdown 代码块**输出。

## 正常验收模板

```md
# QA 验收结果

执行线程：
- QA验收线程

任务ID：
- <MMDDTxxx>

状态：
- 已通过 / 未通过 / 阻塞

更新时间：
- <YYYY-MM-DD HH:mm TZ>

验收线程：
- QA验收线程

验收对象：
- <被验收线程 + 任务ID>

验收范围：
- <本轮验收边界>

验收步骤：
1. <步骤 1>
2. <步骤 2>
3. <步骤 3>

实际结果：
- <事实 1>
- <事实 2>
- <事实 3>

验收结论：
- 已通过 / 未通过 / 阻塞
- 结论说明：
  - <一句话总结>

通过项：
1. <通过项 1>
2. <通过项 2>

不通过项：
1. <不通过项 1> / 无

缺陷清单：
1. <缺陷 1> / 无

阻塞项：
- <阻塞项> / 无

建议总控下一步：
1. <建议 1>
2. <建议 2>

提交信息：
- commit：<commit id> / 无
```

## 免内容验收模板

当派发文本明确写了：

- `QA验收方式：免内容验收`

则使用这个模板。

这时 QA 不审核任务内容本身，只确认流程节点已经走完。

```md
# QA 验收结果

执行线程：
- QA验收线程

任务ID：
- <MMDDTxxx>

状态：
- 已通过 / 阻塞

更新时间：
- <YYYY-MM-DD HH:mm TZ>

验收线程：
- QA验收线程

验收对象：
- <被验收线程 + 任务ID>

验收方式：
- 免内容验收

验收范围：
- 本轮只做流程确认，不审核任务内容本身。

实际结果：
- 本轮为免 QA 内容验收任务
- QA 未审核任务内容
- QA 只完成流程确认

验收结论：
- 已通过 / 阻塞
- 结论说明：
  - 本轮 `已通过` 仅表示流程节点已走完，不表示 QA 已对任务内容做最终裁决。

通过项：
1. 流程节点已完成

不通过项：
1. 无

缺陷清单：
1. 无

阻塞项：
- <阻塞项> / 无

建议总控下一步：
1. 由总控继续判断任务内容是否成立。

提交信息：
- commit：无
```

## QA 输出规则

- 对正常任务，QA 是最终验收事实源
- 对免内容验收任务，QA 不是任务内容的最终判断者
- QA 文档应始终只保留最新有效结果，不要混写成历史流水账
