# 任务派发模板

总控给真实线程派发任务时，统一使用这份模板。

整段文本必须用**可直接复制的 Markdown 代码块**输出。

## 标准派发模板

```md
执行线程：
- <线程名称>

任务ID：
- <MMDDTxxx>

标题：
- <任务标题>

简短描述：
- <1-2 句摘要>

状态：
- 待执行

执行顺序：
- 当前唯一任务 / 可并行

前置任务：
- 无 / <前置任务ID>

规则更新提醒：
- 无 / 请先阅读规则文档后再执行本任务。

按线程规则执行：
- <规则文档路径或名称>

是否需要提交代码：
- 需要 / 不需要

提交要求：
- 自测通过后提交 / 不需要提交
- 回报必须带 `commit id` 和 `提交信息` / `commit：无`

是否进行QA验收：
- 是 / 否

QA参与：
- 是 / 否

QA验收方式：
- 正常验收 / 免内容验收 / 无

QA验收线程动作：
- 正常验收 / 不验任务内容，只做流程确认并回写结果 / 无

files：
- <文件或模块范围>

action：
- <这轮实际要做什么>

verify：
- <这轮需要跑什么验证>

done：
- <回报时必须说明什么>
```

## 派发规则

- 默认一次只正式派发 1 个任务
- 只有多个任务彼此独立、可并行时，才允许一次派发多个任务
- 如果多个任务可并行，必须明确写：
  - `执行顺序：可并行`
- 如果多个任务有依赖关系，不要批量派发

## QA 相关写法

### 正常验收任务

使用：

- `是否进行QA验收：是`
- `QA参与：是`
- `QA验收方式：正常验收`
- `QA验收线程动作：正常验收`

### 免内容验收任务

使用：

- `是否进行QA验收：是`
- `QA参与：是`
- `QA验收方式：免内容验收`
- `QA验收线程动作：不验任务内容，只做流程确认并回写结果`

### 当前暂不进入 QA 的任务

使用：

- `是否进行QA验收：否`
- `QA参与：否`
- `QA验收方式：无`
- `QA验收线程动作：无`

## 规则更新提醒

当工作流规则刚更新过时，每个活跃线程收到的下一条第一任务，应带一次提醒：

```md
规则更新提醒：
- 请先阅读规则文档后再执行本任务。
```

这条提醒在同一轮里，对同一个线程只展示一次。
