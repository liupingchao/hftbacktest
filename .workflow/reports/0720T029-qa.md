缺陷清单：
1. **P2 - Disconnect event 后 pump 预取下一次 source read，manager cycle 返回后仍发起 reconnect**
   - 位置：
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:1604`
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:1618`
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:1710`
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:3313`
   - 原因：
     - Pump 成功 `put()` 一个 event 后，不等待交易线程消费/ack，立即进入下一次 `next(source_iterator)`。
     - Main thread 收到 disconnect 后只设置 `pump_stop`，没有 source close、stop acknowledgement 或 bounded join。
     - Built-in generator 在 disconnect yield 之后仍会执行 reconnect sleep，并可再次调用 `_connect_websocket`；`pump_stop` 只能在该 `next()` 返回后被检查。
   - 复现：
     - Fake 第一次 `_connect_websocket` failure，使 built-in source yield disconnect。
     - Observer fail closed，manager 两侧 cancel 和 final proof 完成。
     - 完整 manager cycle 返回后 `0.243857s`，source 仍发起第二次 connect，pump thread 仍存活。
   - 影响：
     - Cancel deadline 不受影响，因此不是 P1。
     - 但 manager lifecycle 已结束后仍存在 orphaned public-source work；真实 disconnect 路径可继续建立 websocket、消费并丢弃消息或占用资源。
     - 这直接违反任务 stop condition：background public read 不得在 manager cycle 后继续消费且缺少 bounded stop path。
   - 测试缺口：
     - 现有 timeout test 只检查传给 source 的 `websocket_timeout`，没有检查 disconnect 后 connect call count、pump thread termination 或 source close。

阻塞项：
