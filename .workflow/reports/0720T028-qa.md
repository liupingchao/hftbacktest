缺陷清单：
1. **P1 - 5 秒 websocket recv 可把 3 秒 manager hold/cancel deadline 延长到约 5 秒**
   - 位置：
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:8416`
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:8539`
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:3198`
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:3221`
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:1597`
     - `examples/hyperliquid/hyperliquid_tiny_live_m2_public_watcher.py:555`
   - 复现：
     - 使用默认 `run_event_driven_inline_reprice_live(..., quote_hold_seconds=3, use_exchange_reconciled_manager=True)`。
     - Inline live source 固定传入 `yield_timeouts=True`，但 socket timeout 仍按全局 watcher 剩余时间取 `min(5.0, remaining)`。
     - Manager hold observer 在循环中同步调用 `next(source_iter)`；若提交后没有立即收到公共消息，该调用会停在 `ws.recv()`，observer 无法在 3 秒 hold deadline 主动中断。
     - 直到最多 5 秒 recv timeout 或消息到达后，observer 才记录 overrun/fail-closed 并返回；`cancel_all_owned()` 在其后才开始。
     - 最小 hostile probe 将 source 的一次 `next()` 阻塞 3.6 秒；3 秒 hold 下首个 cancel 实测晚于 deadline `0.600s`，cycle elapsed `3.621s`。
   - 影响：
     - 正常 3 秒 resting quote 可额外暴露约 2 秒，最长约为目标 hold 的 `166.7%`。
     - `deadline_overrun` 只是事后证据状态，不能追回已经延迟的 cancel。
     - 在快速行情中会增加 stale quote fill、adverse selection 和仓位风险；这直接违反“公共事件收集不得改变 cancel sequencing/timing”的任务 stop condition。
   - 测试缺口：
     - 现有 observer failure test 只覆盖 observer 立即抛错后仍 cancel，没有覆盖默认 websocket iterator 的阻塞 recv。
2. **P2 - Replay quarantine 可 fail open，空 manager contract 仍可能信任持久化 confirmed exposure**
   - 位置：
     - `examples/hyperliquid/cross_exchange_online_estimators.py:2784`
     - `examples/hyperliquid/cross_exchange_online_estimators.py:2824`
     - `examples/hyperliquid/cross_exchange_online_estimators.py:2847`
     - `examples/hyperliquid/cross_exchange_online_estimators.py:2876`
     - `examples/hyperliquid/cross_exchange_online_estimators.py:3000`
   - 复现：
     - 最小 probe 提供 invalid manager interval，使重建 exposure 为空、quarantine 为 `1`；source core snapshot 同为零 exposure，结果 `snapshot_match=true`。
     - `snapshot_match` 只要求 snapshot hash 和 exposure comparison 相等，不要求 `confirmed_resting_exposure_quarantine_row_count == 0`，CLI 因而可 exit `0`。
     - 第二个 probe 写入仅表头 contract CSV 和 `1` 条 forged `resting_confirmed=true` exposure；空列表与 v1 “contract absent” 被同样处理，结果 persisted confirmed `1`、rebuilt confirmed `0`，但 `snapshot_match=true`。
   - 影响：
     - 单独使用 estimator replay manifest/CLI 时，invalid manager evidence 可能被误标为 replay pass。
     - Task 12 acceptance 当前另有 quarantine-empty check，可阻断完整 acceptance；但 replay 自身不满足任务要求的 fail-closed evidence gate。
