实际结果：
- halt state 使用独立用户级 control directory；首次报价必须有显式 `armed`/`reset` 状态，缺失 root/file、损坏 JSON、缺字段、错误 schema、失败/pending resolution 均 fail-closed。
- trigger 先原子写入 `triggered`，再执行撤单和 proof；`execute_kill_switch` 使用 fcntl lock 覆盖完整序列，重复/并发调用不会重复 cancel/flatten。
- cancel response 和 market-close response 的非异常 error/rejected payload 均阻断后续成功结论；任一失败保持 halted。成功 flatten 后只有到期状态可恢复，失败/pending 不会因时间到期自动恢复。
- long/short 均按真实 `szi` 的 `abs(szi)` 调用 SDK `market_close`；flat 不调用 market close；残余仓位达到 lot tolerance 时 fail-closed。
- open-orders proof 对任意非空或无法归属的账户 open order fail-closed，不静默忽略未登记订单。
- watcher、fill-window 和 `run_order_once` 在同一 control state 上做入口、每 attempt 和最终 order-submit gate；最终状态读取与 `client.order()` 共用同一 fcntl 临界区，endpoint evidence 只在真正越过 gate 后标记。
